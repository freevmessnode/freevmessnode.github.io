Armbian 上运行 Clash：轻量级单板电脑的科学上网完全攻略

引言：当极简系统遇上强大代理

如果你拥有一块树莓派、Orange Pi 或其他 ARM 架构的单板电脑，并且正在为“如何在低功耗设备上实现稳定、灵活的网络代理”而苦恼，那么 Armbian 与 Clash 的组合几乎是为你量身定制的答案。Armbian 作为一个为 ARM 设备优化的 Debian/Ubuntu 衍生系统，其干净、高效的内核与 Clash 这款规则引擎强大的代理工具相遇，注定会产生化学反应。本文将以第一视角，带你从头梳理在 Armbian 上部署 Clash 的每一个细节，并分享一些比官方文档更“接地气”的经验。

第一章：为什么是 Armbian + Clash？

在深入命令行之前，我想先聊聊为什么这对组合值得你花时间。市面上有 OpenWrt、有各种图形化代理工具，但 Armbian 的优势在于它的“纯粹”——它不预设任何网络策略，把所有控制权交给你。而 Clash 的核心理念是“分流”，它不盲目代理所有流量，而是根据你定义的规则（比如国内直连、国外代理、广告拦截）智取网络请求。

这带来了三个实际好处： 1. 资源占用极低：Armbian 空载内存占用可低至 50MB 左右，Clash 本身仅需 20-30MB 内存。这意味着你可以在 512MB 内存的旧板子上跑得飞起。 2. 规则自由度极高：你可以为不同的域名、IP 段、甚至进程指定不同的出口节点，实现真正的“智能路由”。 3. 无头模式友好：Clash 默认提供 RESTful API 和命令行控制，完全不需要图形界面，这恰好与 Armbian 的服务器定位完美契合。

第二章：准备工作与核心下载

2.1 确认你的架构

首先，打开终端，输入 uname -m。绝大多数 64 位 ARM 设备（如树莓派 4B、RK3399 等）会返回 aarch64。但请注意，Clash 官方发布包中，arm64 版本对应的是 aarch64，而 amd64 对应的是 x86_64 架构（部分用 Intel NUC 跑 Armbian 的用户需要关注）。本文以最常见的 amd64 版本为例（因为许多教程默认如此），但如果你用的是 ARM 板子，请将下文命令中的 clash-linux-amd64.gz 替换为 clash-linux-arm64.gz。

2.2 下载与解压

在 /tmp 目录下操作，避免污染主目录：

bash cd /tmp wget https://github.com/Dreamacro/clash/releases/latest/download/clash-linux-amd64.gz gunzip clash-linux-amd64.gz

小提示：如果 GitHub 下载速度不理想，可以使用 ghproxy.com 等镜像前缀，例如： wget https://ghproxy.com/https://github.com/Dreamacro/clash/releases/latest/download/clash-linux-amd64.gz

第三章：安装与文件布局

3.1 移动并赋权

解压后，你会得到一个无扩展名的二进制文件。将其移动到 /usr/local/bin 并赋予执行权限：

bash sudo mv clash-linux-amd64 /usr/local/bin/clash sudo chmod +x /usr/local/bin/clash

验证安装：clash -v 应该输出版本号。

3.2 创建配置目录

Clash 需要两个关键文件：config.yaml（主配置）和 Country.mmdb（GeoIP 数据库，用于规则匹配）。建议统一放在 /etc/clash：

bash sudo mkdir -p /etc/clash sudo chown -R $USER:$USER /etc/clash # 方便普通用户管理

第四章：配置文件——从零到一

4.1 获取基础配置

这里有一个误区：很多人以为必须手动编写 YAML。实际上，你只需要从你的机场（订阅服务商）下载 Clash 订阅链接，或者使用在线生成器（如 Clash Rules Generator）生成一个带规则的基础文件。但为了让教程完整，我提供一个最小可运行的配置骨架：

```yaml

/etc/clash/config.yaml

mixed-port: 7890 allow-lan: true mode: rule log-level: info

proxies: - name: "my-server" type: ss server: example.com port: 8388 cipher: aes-256-gcm password: "your-password"

proxy-groups: - name: "PROXY" type: select proxies: - "my-server"

rules: - GEOIP,CN,DIRECT - MATCH,PROXY ```

注意：请将 proxies 部分替换为你真实可用的节点信息。如果你有订阅链接，可以直接下载： bash curl -L "你的订阅链接" -o /etc/clash/config.yaml

4.2 下载 GeoIP 数据库

Clash 启动时需要 Country.mmdb 文件，用于 GEOIP 规则判断。从官方或镜像下载：

bash cd /etc/clash wget https://github.com/Dreamacro/maxmind-geoip/releases/latest/download/Country.mmdb

第五章：启动守护进程与自启动

5.1 手动启动测试

首次启动建议前台运行，观察报错：

bash clash -d /etc/clash

看到类似 time="..." level=info msg="RESTful API listening at 127.0.0.1:9090" 的日志，说明启动成功。按 Ctrl+C 停止。

5.2 使用 systemd 管理

为了让它常驻后台并开机自启，创建一个服务文件：

bash sudo nano /etc/systemd/system/clash.service

填入以下内容：

```ini [Unit] Description=Clash Daemon After=network.target

[Service] Type=simple User=root ExecStart=/usr/local/bin/clash -d /etc/clash Restart=on-failure RestartSec=5

[Install] WantedBy=multi-user.target ```

保存后执行：

bash sudo systemctl daemon-reload sudo systemctl enable clash sudo systemctl start clash

查看状态：sudo systemctl status clash。若为 active (running)，则大功告成。

第六章：配置代理环境变量与测试

Clash 默认监听 7890 端口（mixed-port，HTTP 和 SOCKS5 共用）。要让系统流量走代理，你需要设置环境变量：

bash export https_proxy=http://127.0.0.1:7890 export http_proxy=http://127.0.0.1:7890 export all_proxy=socks5://127.0.0.1:7890

测试连通性：

bash curl -I --max-time 10 https://www.google.com

如果返回 HTTP 200，恭喜你，代理已生效。

第七章：高级技巧与避坑指南

7.1 规则优化：直连与代理的平衡

默认规则是 GEOIP,CN,DIRECT，这意味着国内 IP 直接连接，国外走代理。但某些国外 CDN（如 Cloudflare）在国内访问可能更快，你可以手动添加规则：

yaml rules: - DOMAIN-SUFFIX,cloudflare.com,DIRECT - GEOIP,CN,DIRECT - MATCH,PROXY

7.2 日志轮转与磁盘占用

Clash 日志默认输出到 stdout，由 systemd 管理。长期运行会产生大量日志。建议编辑服务文件添加：

ini StandardOutput=null StandardError=journal

或者只保留错误级日志：log-level: error。

7.3 内核参数优化

为了提升并发连接性能，建议开启端口转发并调整文件描述符限制：

bash sudo sysctl -w net.ipv4.ip_forward=1 ulimit -n 65535

若要永久生效，编辑 /etc/sysctl.conf 添加 net.ipv4.ip_forward=1。

第八章：常见故障排查

8.1 “level=error msg=... dial tcp: i/o timeout”

通常是节点本身不可用或网络出口被封锁。尝试更换节点，或检查防火墙是否放行 UDP 端口（部分协议需要）。

8.2 “no such file or directory: /etc/clash/Country.mmdb”

忘记下载 GeoIP 数据库。重新执行 4.2 节的命令。

8.3 端口被占用

使用 sudo netstat -tulpn | grep 7890 检查。若被占用，修改 mixed-port 为其他值，例如 7891。

8.4 无法访问局域网内设备

检查配置中 allow-lan: true 是否开启。如果开启后仍无法访问，可能需要将 bind-address: '*' 添加到配置文件中。

FAQ

Mellow 如何配置透明代理？
Mellow 的透明代理功能可通过 TUN 模式或 WinDivert 实现。启用后系统流量会自动通过代理转发，无需手动设置浏览器代理，适合全局科学上网场景。
WinXray 如何实现延迟最低节点自动切换？
WinXray 支持节点延迟检测和策略组配置，可自动将流量切换至延迟最低的节点。用户无需手动选择，提高游戏、视频和网页访问速度及稳定性，优化整体网络体验。
Nekoray 的内置延迟测试为什么与系统 ping 不同？
客户端的延迟测试通常基于 TCP 或特定探测包，而系统 ping 使用 ICMP，两者网络路径与优先级可能不同。此外，防火墙或服务器对 ICMP 的响应可能被限制，导致测试结果存在差异。
如何给 Clash 添加自定义域名白名单以提升访问体验？
在 rules 中添加 `DOMAIN-SUFFIX,example.com,DIRECT` 或 `DOMAIN-KEYWORD,example,DIRECT` 条目，将常用且可靠的站点设为直连，可减少代理绕行延迟并避免因代理造成的登录/验证问题。
Clash 的 Rule Provider 有什么作用？
Rule Provider 是 Clash 的规则分发机制。用户可以订阅不同的规则集，比如广告拦截、社交媒体、流媒体等，实现按需加载。它让配置文件更加简洁、动态更新，并支持多源规则管理。
如何使用 Clash 配置订阅链接？
在 Clash 中添加订阅链接时，用户需复制提供的 URL 并在客户端的配置界面中粘贴。Clash 会自动下载并更新配置文件。通过订阅，用户可以一键更新节点信息，无需手动导入，适合长期维护多个节点来源的用户。
Shadowrocket 的重写功能有什么用途？
Shadowrocket 的重写功能允许用户在请求阶段修改 HTTP 头、响应内容或重定向 URL。这一功能常用于屏蔽广告、解锁区域限制或调试网页请求，非常灵活强大。
Mellow 的 TUN 模式适合哪些应用？
TUN 模式拦截系统 IP 层流量，可实现全局代理。适合游戏、视频、浏览器和其他全局应用，实现低延迟和稳定连接，保证所有流量通过代理节点，提高访问速度和稳定性。
VMess 的 TLS+伪装模式适合什么情况？
TLS+伪装模式能隐藏真实流量特征，适用于封锁严格的环境。结合域名伪装和证书配置，可以使流量看似普通 HTTPS 请求，提高安全性和抗封锁能力。
SSR 的混淆参数该如何填写？
SSR 混淆参数位于节点配置中，通常选择如 tls1.2_ticket_auth 或 http_simple。参数字段可以自定义伪装主机或路径，以模拟正常流量行为，从而提高隐蔽性和抗封锁能力。
